**Sublayer:** 0d Harness & session

**Goal.** `bin/seat` counts and reads every session it starts, wherever its run folder is. Today it reads only run folders one level under `~/factory-runs`. A session in a deeper folder is invisible to the cap of live sessions on a seat, and its rate-limit rejection does not take the seat out, so the seat is picked again and the next session fails at once.

Decided by the Human:
- 2026-11-05, on INN-25: kept in Triage, to be built after release 1 ([record](https://github.com/tuannd9288/factory/issues/200#issuecomment-6651162870)).

**Acceptance.**
- A seat's cap counts a live session whose run folder is nested deeper, and a rejection recorded there takes that seat out until its reset.
- A seat's rejection stays known while its reset is ahead, even after the run folder that recorded it is moved or archived ([record](https://github.com/tuannd9288/factory/issues/200#issuecomment-6527101346)).
- One fix covers this issue, #201 and #409: a port of agent-orchestrator's usage read in place of today's account events in `bin/lib/seat.mjs`.
- Until it is fixed, every run folder sits directly under `~/factory-runs` ([record](https://github.com/tuannd9288/factory/issues/200#issuecomment-6526855471)).

**Limits.**
- Probe and fixture trees, with their made-up rate-limit events, must never reach the seat pick.
- Score: 2 × 4 = 8. Four real run folders out of about 225 sat deeper, and each costs one failed session.
