**Sublayer:** 2b Skills & plugins

**Goal.** The pack's live verifier never runs a pull request's own code in a process that holds the verifier's Codex login. Today `codex exec` gets that login while it runs the candidate's verify, tests and driver in a sandbox that can read outside the worktree, so the candidate's code can reach the login. The path is inert while no repository names a driver.

Decided by the Human:
- 2026-10-31: a candidate fix is to run the candidate's code in a throwaway VM that holds no login. The choice of VM is his, and the Lead proposes one with evidence ([record](https://github.com/tuannd9288/factory/issues/264#issuecomment-6541978222)).
- 2026-11-04, about 12:40 +07: the Lead proposes the VM, and the build waits until release 1 closes ([record](https://github.com/tuannd9288/factory/issues/264#issuecomment-6623092416)).
- 2026-10-31, evening, his snag rule: a block that piggery, agent-orchestrator or pstack does not solve is parked. None of the references solves this, so it is parked, and reopening it is his call ([record](https://github.com/tuannd9288/factory/issues/264#issuecomment-6649309056)).

**Acceptance.**
- The verifier's login never reaches a process that runs candidate code, for example through a short-lived credential for the run, or reads confined to the worktree, or a throwaway machine.
- A test shows the candidate's code cannot read the verifier's profile folder.
- The fix lays `scripts/live-verify` and its libraries in repositories again, lets `.gate/driver.json` be filled, and imports `process` and `console` from Node so a strict lint passes.
- Proposed and waiting on his three choices: InstaBox as the VM, the free plan to start, and an InstaBox key with only the machine scopes, made by him ([record](https://github.com/tuannd9288/factory/issues/264#issuecomment-6623092416)).
- Shown on 2026-11-05 with a decoy login: the read path is real. A custom Codex permission profile that denies reads outside the workspace blocks it, but is not yet tried in a real verify run ([record](https://github.com/tuannd9288/factory/issues/264#issuecomment-6649309056)).

**Limits.**
- Until it is fixed, no repository fills `.gate/driver.json`.
- A client's repository gets no driver until its client agrees that its code may leave his machines.

**Prior art.**
- dsh `8c32a9d`, `docs/006-deployment.md:19,218,225-227`: it states the same weakness, and isolates with a separate OS user that holds only the agent's credentials.
- zeroshot `docs/concepts/targets.md:57` (the same trust boundary locally, a disposable capsule when hosted), piggery `docs/reference.md:198`, pstack's Cursor cloud agents.
- Codex Cloud removes secrets before the agent runs; GitHub Actions passes no secrets to pull requests from forks.
