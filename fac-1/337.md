**Sublayer:** 3a Required status checks

**Goal.** The gate's trusted checks keep running on public repositories after GitHub enforces its default `pull_request_target` policy on 2026-12-02. From then on, GitHub blocks workflows on that trigger in public repositories that have no explicit policy. The gate's `review`, `verdict` and `tier` run on it, so nothing would merge in the three public repositories with the kit: factory-probe, factory-pack-scratch and factory-onboard-scratch. Private repositories are not affected.

Decided by the Human: nothing yet. The factory-repo session kept it in Triage on 2026-11-02, to revisit before 2026-11-25 or sooner if a public product repository joins ([record](https://github.com/tuannd9288/factory/issues/337#issuecomment-6569156093)).

**Acceptance.**
- Every public repository with the kit keeps its trusted checks running after 2026-12-02, either through an Actions event policy that explicitly allows `pull_request_target`, or by moving the trusted jobs to a trigger the default policy does not block. The pull request says which, and why.
- `bin/onboard-owner` applies and reads back the repository setting this needs, and `--check` reports it missing.
- Evidence before 2026-12-02 that it works: GitHub's policy insights, or a run on a public scratch repository.
- New since filing: the factory repository itself is public, and its `approval` check (#461) now runs on `pull_request_target` too, so it is affected as well.

**Limits.**
- Deadline: 2026-12-02.
- The policy is the Human's to set on each repository. Agents only read it back.
- Open: an event policy or another trigger. GitHub's hardening guide prefers `workflow_run` for privilege separation, which is the larger change.
