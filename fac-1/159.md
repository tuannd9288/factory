**Sublayer:** 2c Verification

**Goal.** `bin/onboard` opens the kit pull request by itself for a repository like zalo-gateway: one that tests with vitest, runs its own lint and size checks over every tracked file, and has a `scripts/verify` that refuses an uncommitted tree. The rehearsal on 2026-10-29 stopped at onboard's verify for three reasons: the kit's test check ran no vitest test, the repository's own checks read the kit's `.gate/` files, and onboard verifies the kit before committing it.

Decided by the Human:
- 2026-11-05, on INN-25: kept in Triage, to be built after release 1 ([record](https://github.com/tuannd9288/factory/issues/159#issuecomment-6651165714)).

**Acceptance.**
- onboard commits the kit, verifies that commit, and leaves the commit unpushed when verify fails, so a verify that checks a commit passes on a good kit.
- The kit pull request's body names any repository check that reads `.gate/`, or the kit offers one place to exclude it.
- For a vitest, jest or pytest repository, onboard proposes the test and prepare commands, or says plainly that they are still the `node --test` defaults.
- A self-hosted runner's needs, at least `gh`, `node` and `git`, are named or checked before the first gate run. On the first such pull request the trusted jobs failed closed for want of `gh` ([record](https://github.com/tuannd9288/factory/issues/159#issuecomment-6493060725)).
- Open: whether the second and third points belong in onboard at all, or stay the repository session's job.

**Limits.**
- No change to how the trusted verify runs on CI.
