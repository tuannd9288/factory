# The factory's parts: keep or cut (#271, FAC-8, phase 1)

This is the proposal. Nothing is cut until the Human says yes to `cutback/page-vi.md`. It was measured on `main` at `37ce95a`, 2026-11-06.

## How it is measured

One command measures every row and runs the check: `node cutback/check.mjs --rows`.
- **Lines** are every line (`wc -l`) of the part's tracked files under `bin/`, `kit/`, `packs/` and `modules/`, tests excluded. Code, JSON and the pack's prose all count.
- **Tests** are the `test(` calls in the part's test files: `grep -cE '^\s*test(\.\w+)?\(' <file>`. `test/kit.test.mjs` covers about ten kit parts, so a row names its top-level `describe` block as a line range, and only those lines are counted: `sed -n A,Bp test/kit.test.mjs | grep -cE '^\s*test(\.\w+)?\('`.
- A test made in a loop counts once. Tests were counted, not run.

## The words in the keep-or-cut column

- **keep:** the part serves a release-1 goal, a settled decision, or what a reference system does. **keep, trim** means a named piece inside the part goes, and the row still counts as kept.
- **planned:** it was already set to go before this page. The source is named.
- **cut:** proposed here. No goal needs it, and no reference system does it, or a reference system does it in another way that the factory already has.
- **his word:** a cut that changes one of his settled decisions (`docs/decisions.md`). It goes only if he agrees, as #271's limits say.
- **his call:** #271 leaves this choice to him, or the part is an option he has not picked yet.
